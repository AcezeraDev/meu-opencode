Open a page in the built-in browser, or move between pages and tabs.

This is a real Chromium browser: JavaScript runs, single page apps render, and
logins persist between sessions in a dedicated profile. Prefer it over webfetch
whenever a page needs scripting to show its content, requires being signed in,
or has to be interacted with.

The browser belongs to this conversation, with the user's logins. Do the
browsing yourself: a subagent (task) cannot see your tabs or use this browser.

PDFs: navigating to a PDF (or a link that turns out to be one) returns its text,
page by page, instead of an outline; the file is downloaded and read directly,
with the site's session when it needs a login. There is nothing to click in a
PDF, so read what you need and carry on.

By default the tool returns the page outline after navigating, so you usually do
not need a separate browser_snapshot call. Every actionable element in that
outline carries a ref like `ref_12`, which browser_act uses to click or type.

Actions:
- goto: open `url` in the current tab (default)
- back / forward / reload: history navigation
- new_tab: open `url` in a new tab and make it active
- select_tab: switch to the tab given by `tab`
- close_tab: close the tab given by `tab`, or the active one
- list_tabs: list open tabs without navigating
- close_browser: shut the browser down and release its memory
- open_external: open `url`, or the current page, in the user's own browser

Refs stay the same while their element stays on the page, so they keep working
across browser_act and browser_batch calls. A new page gets new refs: act on
the refs from the outline of the page you are on.

Some sites turn automated browsers away with a bot check, a captcha or an
"Access denied" page. When navigating or acting lands on one, the page is
handed to the user's own browser automatically and the output says so (with a
`blocked:` line) instead of showing the page. When that happens, tell the user
the page is open in their browser and leave that site to them: retrying it here
will not get past the block.

open_external is for the same situation when it was not detected, or when the
user asks for it. The tab it opens is out of your reach: you cannot see, read
or control it. So do not use it for pages you still need to work on.
